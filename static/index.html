📖 RAG System — User Manual

1. What This System Does

This is a Retrieval-Augmented Generation (RAG) system. It answers questions strictly from your uploaded documents — not from the AI model's own knowledge. Every answer is grounded in a specific passage and attributed back to its source page. If the answer isn't in your documents, the system says so rather than inventing one.

Supported document formats: .pdf (multi-page, page-tracked) and .txt (UTF-8 or Latin-1).

2. How the Pipeline Works

  1. Upload → Text is extracted from every page of your PDF or TXT file.
  2. Chunking → Document is split into overlapping ~500-character segments preserving sentence boundaries.
  3. Embedding → Each chunk is converted to a 384-dimensional vector using all-MiniLM-L6-v2 (runs locally, no API call).
  4. Indexing → Vectors are stored in a FAISS in-memory index using exact Cosine Similarity.
  5. Query → Your question is embedded and compared against all chunk vectors. Top-3 most similar chunks are retrieved.
  6. Relevance Gate → If no chunk scores ≥ 0.30 cosine similarity, the answer is not found — no LLM is called.
  7. Generation → Retrieved chunks are injected into a strict LLM prompt. The model can only answer from the given context.

3. How to Use

  1. Upload a Document — Drag & drop a PDF or TXT onto the Document Ingestion zone, or click to browse. Wait for the "Successfully indexed" confirmation.
  2. Ask a Question — Type in the search bar and press Ask Question, or click any suggested query pill below the bar.
  3. Read the Answer — The Grounded Response card shows the answer. Expand the Source Attribution section below it to see the exact document passages used, with page numbers and similarity scores.
  4. Summarize a Document — Click the Summarize button next to the search bar for a full executive summary of all indexed documents.
  5. Summarize Specific Files — Use the checkboxes next to each file in Indexed Files to select specific documents, then click Summarize (N).
  6. Summarize Pasted Text — Click Paste Custom Text / Profile below the search bar, paste any raw text, and click Summarize Text.
  7. Dynamic Suggested Queries — After uploading, the query pills automatically update to reflect questions tailored to your document's actual content. Selecting a single file also refreshes the suggestions for that file.
  8. Reset the Index — Click Clear / Reset Index in the sidebar to wipe all indexed documents and start fresh.

4. Understanding the Results

  • 100% Grounded badge — Answer was generated strictly from retrieved document passages.
  • Latency badge — End-to-end time from submitting your question to receiving the answer.
  • Similarity score (e.g. 0.73) — Cosine similarity between your question and the retrieved chunk. Range 0–1; higher = more relevant. Threshold is 0.30.
  • Page number — Exact page in the original PDF where the source chunk was found.
  • "The answer could not be found in the provided documents." — No chunk was similar enough to your question. The system did not hallucinate; try rephrasing or upload a more relevant document.

5. API Reference

  • GET /health — System status, indexed document count, and document list.
  • POST /documents/upload — Ingest a PDF or TXT file (multipart/form-data).
  • POST /documents/reset — Clear all indexed documents and vectors.
  • POST /documents/summary — Generate executive summary for selected documents or raw text.
  • GET /documents/suggestions — Return dynamically generated query suggestions from indexed content.
  • POST /query — Ask a question; returns grounded answer + source chunks.

6. LLM Cascade & Offline Mode

The system tries three answer sources in order:

  1. Google Gemini (if GEMINI_API_KEY is set in .env)
  2. OpenAI GPT-4o-mini (if LLM_API_KEY is set)
  3. Local Extractive Fallback — deterministic, no API needed, always works offline

Embeddings always run locally using all-MiniLM-L6-v2 — no API key required for document indexing or retrieval.
